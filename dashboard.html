Prefix-cache hit ratio — the headline

1 − Σ nISL / Σ ISL: the share of input tokens already in cache (cISL) and free to skip. Append-only ReAct/CodeAct agents cluster at 93–97% — nearly all input is reused prefix. Moatless, a state machine that rebuilds its prompt per phase, collapses to 36%. The verifier is a single call, so nothing to reuse.

ISL ≫ OSL — the agentic signature

Per-call input vs output at the median (log scale). For agents input is 50–200× larger than output — prefill-heavy / decode-light. The ShareGPT chat baseline (bottom) is only ~2.4×: balanced. Same prefix-cache mechanism, opposite request shape.

What it means

  • Append-only histories are near-perfectly cacheable. Each turn appends a tool result to a growing transcript, so 93–97% of every prompt is a cache hit. AxT: 2.32 billion input tokens → only 70M ever need real prefill.
  • Architecture, not task, decides cache behavior. Moatless solves the same SWE tasks but rebuilds its prompt per phase → 36% hit, 95% of sessions shrink context. ~2.7× more prefill per cached token.
  • Prefill-heavy / decode-light. ISL is 50–200× OSL at the median — the opposite of ShareGPT chat, and the reason prefix caching is the dominant cost lever for agents.
  • KV tail is brutal. Peak-context p99 hits 60–100k tokens = 16–25 GiB of KV on a 32B model, vs ~4 GiB median.
How this maps to Frontier (arXiv 2605.21312): Frontier simulates vLLM's block-hash prefix cache and reports ~37% hit on its SharedGPT replay. Our append-only agents (93–97%) sit far above that because agent histories are near-perfectly append-only; Moatless (36%) lands right in Frontier's regime — precisely because it isn't append-only.
Caveats: cISL split is append-only arithmetic (exact for ReAct/CodeAct, approximate for Moatless); OSL excludes hidden reasoning (non-reasoning models); no real CPU-core-seconds — only riptide-at-runtime measures cache-% and CPU. Heavy sets sampled.
